# Лугова Аміна — ДЗ-2, v1 (Google Docs, текст надіслано куратором 16.11.2026)

Inception: Conceptualize, Discover, Specify · Development: Construct, Validate, Deliver · Run

Executive Sponsor – спонсор, людина, яка насичує проект фінансами. Може брати  участь на всіх етапах, на фазі Inception Conceptualize, підтримує ідею, фінансує проект(Discover). Впродовж етапу Development Construct, Validate спілкується з командою виконавців, слідкує за розробкою проекту за планом, потім на кроці Deliver знайомиться з готовим продуктов . На етапі Run може виступати безпосереднім користувачем.  Виступає на боці замовника, але це залежить від типу компанії.

Salesman – продажник, що шукає замовників. Основана робота на етапі Inception Conceptualize, Discover знайти замовника та познайомити його зі своєю компанією та її можливостями, досвідом. і заключити договір з клієнтом.  Виступає на боці виконавців.

Project Manager – відповідальна особа за проект. Може вступити на етапі Inception Discover, знайомиться із замовником, вивчає його бізнес та направлення, обговорює всі деталі проекту. На етапі Development виконує своє основне призначення, координує всю роботу проекту, слідкує за кожним етапом розробки, в постійному контакті з командою і усіма стейкхолдерами (Construct координує розробку, Validate стежить за тестуванням та виправленням помилок, Deliver розсилає документації, навчає користуватися продуктом  ). Може бути і на етапі Run, якщо це продуктова компанія. Є на боці виконавців.

Program Manager – менеджер, керуючий групою проектів. Може вступити на етапі Inception Discover, адже проект може входити в його программу. На етапі Development Construct продовжує спілкуватися з Project Manager, щоб слідкувати чи все йде за планом та чи коректно проект виконується для його програми, на кроці Deliver звіряється з кінцем результатом . На етапі Run аналізує впроваджену програму.   Виступає на ролі виконавця, але може входити й в компанію замовників.

Project Portfolio Manager – керуючий портфелем проектом. На етапі Inception Discover обирає, які проекти запускати, які є ризики запуску, обирає пріоритетні проекти та програми. На етапі Development Construct стежить за планом,  результатами(Deliver). На етапі Run досліджує чи виконує проект заплановану ціль, планує подальші інвестиції. Виступає виконавцем, але може бути вихідцем із компанії замовника.

Product Manager – знає ринок, пропонує замовнику потрібний функціонал та впроваджує його. На етапі Inception Discover аналізує ринком, визначає потреби та функціонал, що є основною його задачею. На етапі Development Construct спілкується з командою, пріоритизує функції, перевіряє чи відповідає продукт задуму(Deliver). На етапі Run стежить за результатами, аналізує відгуки, планує покращення. Виступає на боці замовника.

Business Analyst – визначає написання вимог. В основному працює на етапі Inception Discover визначає та формує вимоги до проекту. На етапі Development  Construct знайомить команду з цими вимогами, стежить за розробкою чи відповідповідають вони вимогами(Deliver) та уточнює деталі. На етапі Run аналізує нові потреби. Виступає на боці виконавця, але компанія замовника також може використовувати свого фахівця.

System Analyst – визначає написання вимог до системи. На етапі Inception Specify допомагає визначити технічні вимоги. На етапі Development Construct основна робота,  допомагає команді розробників, описує систему логіку. На етапі Run може аналізувати технічні зміни то проблеми. Виступає на боці виконавця, але також може з відділу замовника.

Subject-matter expert (SME) – людина, яка знається на конкретній сфері. Основна задача на  етапі Inception Specify ділиться експертними знаннями та уточнює вимоги. На етапі Development Construct консультує команду, перевіряє правильність виконання у своїй предметній області. На етапі  Run оцінює проблеми роботи та допомагає у покращенні. Може виступати на боці обох сторін.

Architect – спеціаліст з архітектури, вибору інструментів, технологій і т.д. На етапі Inception Specify визначає структуру системи. Основана робота на етапі  Development Construct супроводжує, координує реалізацію архітектури. На етапі  Run може брати участь у зміні архітектури та її масштабуванні.

Development Team – команда розробників, тім-лідерів. На етапі  Inception Specify можуть брати участь в оцінюванні проекту. Основна робота на етапі Development Construct створення самого продукту,  готує продукт до запуску на кроці Deliver. На етапі  Run може за потребою виправляти помилки. Виступає на боці виконавця.

Quality Assurance (QA) – вибирають інструменти для тестування, складають кейси, тестують. На етапі Inception Specify планують підхід тестування, підбирають інструменти та визначають критерії якості. Основна робота на етапі Development Validate складають тест кейси та тестують функціонал. На етапі Run можуть проводити повторне тестування після оновлення. Виступають на боці виконавців.

Quality Control (QC) – проводять рев'ю коду, стежать за процесом контролю якості. На етапі  Inception Specify можуть допомогати визначити критерії якості. Основна задача на етапі  Development Validate перевіряють якість реалізації, проводять рев'ю коду та контролюють дотримання стандартів. На етапі Run можуть повторно перевіряти якість після змін. Виступають на боці виконаців.

Configuration Manager – налаштовує оточення, складає збірки. На етапі  Inception Specify може планувати необхідне оточення. Основна фаза Development Construct, на якій він налаштовує середовище, керує конфігураціями та збірками. На етапі Run може керувати конфігураціями робочого середовища та оновленнями. Виступає на стороні виковців.

Analyst – аналітик, перевіряє коректність збору метрик, підбиває результат про успішність проекту/продукту. На етапі  Inception Specify може допомагати визначити цілі та показники успіху. На фазі Development Construct може перевіряти правильність збору даних і допоміжні метрики. Основний етап Run аналізує фактичні результати використання продукту. Може виступати на обох сторонах.

Professional Services – людина чи група людей, які тестують продукт поза командою. На етапі Inception Specify можуть залучатися до консультацій. за потреби. На основному етапі Development Validate  незалежно тестують продукт. На етапі Run можуть повторно перевіряти продукт після запуску. Виступають на стороні виконавця, але може бути і зі сторони замовника.

Support Team – команда підтримки, супроводу продукту. На етапі Development Deliver команда може допомагати з підготовкою продукту перед запуском. Основна робота на етапі Run зв'язок та підтримка  користувачів, вирішення проблем. Може виступати на обох сторонах, так як підтримку може надавати як команда виконавців , так і власна команда замовника.

UI team – дизайнери, верстальники, юзабілісти. На етапі Inception Specify досліджують потреби користувачів, створюють прототипи та  початковий  дизайн. Основна робота на етапі Development Construct, створюють та реалізують інтерфейс. На етапі Run можуть покращувати дизайн. Виступають на стороні виконавців зазвичай.

End User – кінцевий користувач. На етапі Inception можуть розповідати про свої очікування та потреби. На етапі Development можуть тестувати прототипи, брати учать у перевірці зручності. Основний етап - це  Run, безпосередньо користується готовим продуктом. Виступають на стороні замовника.

Software Engineering Process Group (SEPG) – група людей, які займаються аналізом процесів, їх змін. На етапі Inception Specify допомагають визначити процеси та стандарти майбутньої роботи. На етапі Development Construct аналізую процеси розробки та пропонує покраження. На етапі  Run оцінює ефективність процесів та пропонує  можливі зміни. Виступає на боці виконавця.
