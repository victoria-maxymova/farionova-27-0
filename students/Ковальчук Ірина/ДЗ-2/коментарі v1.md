## Коментарі в таблиці (по порядку рядків)

**0. Загальний — до заголовка «Ролі»**
> Дуже наочна таблиця з галочками, одразу все видно ✅ Невелика підказка: здається, загубився Program Manager. Додай, будь ласка, і його рядок 💜

3. **Executive sponsor**
> Замовник — так 👍 Спонсор супроводжує проєкт протягом усієї розробки, тож поглянь, будь ласка, чи не пропущено один з її етапів 🌸
4. **Salesman**
> Inception і виконавець — так 👌 Продажник передає проєкт команді, щойно починається розробка, тож, можливо, варто ще раз поглянути на етапи після Specify ✨
5. Project manager — без коментаря.
6. **Project portfolio manager**
> Добре ✅ Portfolio Manager контролює проєкт на всіх етапах, від старту до запуску, тож, можливо, варто додати ще кілька 💜 Невелика підказка щодо боку: він стежить за головними етапами проєктів з боку команди, яка їх виконує 🌸
7. Product manager — без коментаря.
8. **Business analyst**
> Дуже логічно, що BA у тебе вже на старті з вимогами 👍 Він лишається з командою до самого кінця розробки, тож, можливо, варто додати ще один етап ✨
9. **System analyst**
> Виконавець — так 👌 System Analyst супроводжує розробку від початку до кінця, тож поглянь, будь ласка, ще раз на останній етап розробки 💜
10. **Subject- matter experts (SME)**
> Обидва боки — так ✅ Експерт допомагає команді аж до запуску продукту, тож, можливо, варто додати ще один етап розробки 🌸
11. **Architect**
> Добре 👍 Архітектор стежить, щоб усе будувалось правильно до самого кінця розробки, тож додай, будь ласка, ще один її етап ✨
12. Development team — без коментаря.
13. Quality assurance (QA) — без коментаря.
14. Quality control (QC) — без коментаря.
15. **Configuration manager**
> Етапи розробки — так 👌 Він налаштовує оточення й складає збірки, поки команда розробляє, тож, можливо, Run тут уже не потрібен 💜
16. **Analyst**
> Construct і Validate — так ✅ Аналітика може знадобитися на будь-якому етапі розробки, тож поглянь, будь ласка, ще раз, де саме працює аналітик 🌸
17. **Professional services**
> Добре, що вони в тебе аж до Run 👍 Ці фахівці контролюють якість протягом усієї розробки, тож, можливо, варто додати ще один етап ✨ І невелика підказка щодо боку: вони перевіряють продукт поза командою розробки 💜
18. **Support team**
> Deliver і Run — так 👌 Підтримка долучається ближче до кінця розробки, тож, можливо, варто ще раз поглянути на етап Specify 🌸
19. **UI team**
> Добре ✅ Дизайнери лишаються з проєктом аж до запуску й після нього, бо дороблюють макети й стани елементів, тож, можливо, варто продовжити їхню роботу далі ✨
20. **End user**
> Run і замовник — так 👍 Невелика підказка: кінцеві користувачі зазвичай долучаються, коли продукт уже запущений, тож поглянь, будь ласка, ще раз на інші етапи 💜 А якщо це зовнішні користувачі, то вони радше третя сторона 🌸
21. **Software Engineering Process Group (SEPG)**
> Виконавець — так 👌 SEPG допомагає команді з технічними питаннями й стандартами саме тоді, коли команда розробляє продукт. Спробуй, будь ласка, залишити лише ці етапи ✨

## Висновок для куратора
- Немає рядка Program Manager.
- Точно: Project Manager, Product Manager, Dev Team, QA, QC (Specify у Dev/QA/QC не коментуємо).
- Етапи: бракує Construct (Executive Sponsor, Portfolio Manager, Prof. Services), Deliver (BA, SA, SME, Architect, Analyst, UI team), Run (Portfolio Manager, UI team); зайве — Salesman на Deliver, Configuration Manager на Run, Support Team на Specify, End User на Conceptualize/Discover/Validate, SEPG на Conceptualize/Specify.
- Не коментуємо: Executive Sponsor і SME на Run, BA на Conceptualize, SA на Discover, Analyst на Discover/Specify.
- Боки: Portfolio Manager → виконавець; Prof. Services → замовник.
- Статус 🟠1.
